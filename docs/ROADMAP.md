### P0 —— 公开部署前必做

| # | 事项 | 实测依据 / 做法 |
|---|---|---|
| 1 | **边缘限流** | `/api/ask` 的限流是进程内 Map + 客户端可控 IP 头，轮换请求头即可绕过；启用 AI 后这是**资金风险**。须在 Cloudflare WAF / KV 或网关层做持久化限流（见 SECURITY.md §2）|
| 2 | **生产环境变量** | `ASK_API_BASE` / `ASK_API_KEY` / `ASK_MODEL` 必须配在托管平台（云平台不会读本地 `.env.local`）；不配则自动纯检索，站点仍可用 |
| 3 | **确认托管平台支持 Node 运行时** | `/api/ask` 用 `node:dns` / `node:net` → Cloudflare Workers 不可用（README「部署」有对照表）|

### P1 —— 值得做，收益明确

| # | 事项 | 实测依据 |
|---|---|---|
| 4 | **4 个路由的数据体积** | `/explore`、`/my`、`/matrix`、`/poster` 各携带 **2427KB** 数据块。字段占比：`benefit` 30.7% + `source` 22.7% + `remark` 18.4% = **72% 只在展开态需要**；折叠态字段合计仅 525KB(22%) → 可降到约 190KB gzip（**4.6×**）。需要改成"列表只带折叠字段、展开时按需取全文" |
| 5 | **把 audit-* 用例补上断言** | 75 个 spec 里 **33 个只 log 不断言**（另有 11 个截图类属正常）。这些用例量过很多真实指标（对比度/触控尺寸/焦点/性能），却不会在回归时失败 —— 等于没守卫。建议优先给 `audit-touch`（触控尺寸）、`audit-contrast`（对比度）、`audit-a11y`（无障碍）、`audit-perf-*`（性能）补阈值断言 |
| 6 | **检索语义化** | 现在是关键词级：问「吸烟有什么危害」，前两名仍是含"危害"的粉尘噪声条目，烟相关排第 3。要质变得加同义词表或上 embedding |

### P2 —— 需要跨大版本 / 属产品取向

| # | 事项 | 说明 |
|---|---|---|
| 7 | **升级到 next 15.5.24+ / 16.3.3+** | 彻底消除两条 critical 公告（AVIF 优化 RCE、Windows 宿主 RCE）。跨两个大版本：React 19、`params`/`searchParams` 变 Promise 等。当前已通过关闭图片优化器端点 + 不在 Windows 上公网部署缓解（SECURITY.md §1）|
| 8 | `/explore` 默认列表是否改「先做顺序」排序 | 目前保持原书章节顺序（标签已改准）；阶段页已改为专属优先 |
| 9 | `/ask` 限流阈值（10 次/分/IP） | 真实用户连续追问会碰到；放宽则需配合 P0-1 的边缘限流 |
| 10 | 问卷历史是否持久化 | 现仅存内存（刷新即失），与"本站不存储问题与回答"的承诺一致，属有意设计 |

### 已知限制（不打算"修"，但要如实告知）

- **AI 路径的端到端验证**依赖自建者自己的 key；纯检索路径始终可用且已充分测试
- **DNS 重绑定**理论上仍可绕过自定义地址的校验（需把连接钉在已解析 IP 上才能彻底消除；按本项目风险级别未做）
- **数据随仓库提供**，因此上游更新需要有人跑 `pnpm build:data` 或等每日 workflow（仓库未推送时 schedule 不会运行）

## MVP（第 1-25 天）

### 目标

- 用户能打开 `housheng.lu`（或测试域名）
- 能看长卷首页、点击印章进条目
- 能用三栏检索器按 5 维度筛选
- 能装急救 PWA、离线用
- 能保存自己的清单
